Medallion architecture

  SOURCES          BRONZE             SILVER              GOLD
  CSV, JSON  ──▶   raw data     ──▶   clean data    ──▶   aggregated data
  APIs, CDC        + metadata         typed, validated    BI / ML / API
                   all strings        no duplicates
                                 └──▶ QUARANTINE (rejected)
Layer Question it answers Golden rule
Bronze What exactly arrived? Never discard anything. Allows reprocessing.
Silver What is the correct version of each record? Right types, one row per entity, rules applied.
Gold What does the business need to see? Aggregations and metrics, modeled for consumption.

ANSI mode is on by default in Spark 4: an invalid cast raises an error instead of returning null.

Operation Fails on invalid value Returns null
Type conversion col.cast("int") col.try_cast("int")
Text to timestamp F.to_timestamp(c, fmt) F.try_to_timestamp(c, F.lit(fmt))
Division a / b F.try_divide(a, b)

Quality rules and quarantine

Instead of deleting bad records, keep them with the reason: you can measure source quality, warn the source team and reprocess.

RULES = {
    "preco_invalido":      F.col("price").isNull() | (F.col("price") <= 0),
    "quantidade_invalida": F.col("quantity").isNull() | (F.col("quantity") <= 0),
}
errors = F.array_compact(F.array(*[F.when(c, F.lit(n)) for n, c in RULES.items()]))
df = df.withColumn("_errors", errors)
valid    = df.filter(F.size("_errors") == 0).drop("_errors")
rejected = df.filter(F.size("_errors") > 0)

Partitioned writes

(silver_df
 .repartition("order_date")      # all rows of a day in the same task
 .write.mode("overwrite")
 .partitionBy("order_date")
 .parquet(SILVER))
  • Good partition columns have low cardinality and are used in filters
  • Each task writes one file per partition it finds: without the repartition, you get the small files problem
